# GS290 MegaSuite v0.2.0 — J2ME + ПК в одном цикле

## 1. Телефон (CLDC 1.1, MIDP 2.1)

Установить поверх v0.1.2 оба файла из GitHub Actions:
- `GS290NativeProbe-Control.jar`
- `GS290NativeProbe-Control.jad`

Версия `MIDlet-Version: 0.2.0`, имя приложения/производитель сохранены.
На главном экране выбрать **Run ALL**. Это запускает один поток
последовательных безопасных тестов, приблизительно 40–60 проверок (число
зависит от набора JSR/API телефона). После завершения приложение пытается
создать `GS290_Mega_*.txt` в первом доступном файловом корне через JSR-75.

Если автоматическое сохранение не удалось из-за разрешений/накопителя,
использовать **Save TXT** и выбрать носитель вручную. Текстовый отчёт
включает как прежние Java / DEFLATE / RMS результаты, так и весь MegaSuite.

**Основные области тестирования:**
- свойства CLDC/MIDP и характеристики платформы;
- 13 потенциально доступных Java API (обнаружение класса не равно правам);
- 5 статусов разрешений;
- побитовая арифметика, байты, массивы, bounds checking, UTF-8;
- 4 небольших проверки Java-кучи, сборщик мусора и создание потока;
- чтение одного корректного DEFLATE-ресурса побайтово и блоками,
  контрольная сумма и отсутствующий ресурс;
- создание/изменение/чтение/удаление временной записи RMS;
- JSR-75 обнаружение файловых корней без записи в ходе самой проверки.

Состояние **MEGA:RUNNING** записывается в RMS перед запуском и
**MEGA:FINISHED** после; если после прерывания осталась RUNNING,
это лишь факт незавершённой проверки, не подтверждение RCE.

### Чего тест не делает

Не запускает повреждённый DEFLATE на телефоне, не выводит произвольную
RAM/ARM-регистры, не выполняет команды ОС, не трогает загрузчик/прошивку.
Нативное исполнение и соответствие версии V10k исследованной V10C
остаются **неподтверждёнными**.

## 2. ПК: сводка существующих прогонов и отчёта телефона

Скрипт использует только Python 3 stdlib. Для объединения уже полученных
данных V10C MegaLab v8 с TXT-отчётом телефона:

~~~powershell
py -3 .\tools\gs290_pc_megasuite.py `
  --phone-report "GS290_Mega_1234.txt" `
  --v8-report "jvm_mega_results.zip" `
  --firmware "I:\LG-GS290-Rebirth\results\extracted\firmware" `
  --out "GS290_Combined_Results"
~~~

Для нового большого прогона с Unicorn (768–4096 случаев):

~~~powershell
py -3 -m pip install unicorn capstone
py -3 .\tools\gs290_pc_megasuite.py `
  --phone-report "GS290_Mega_1234.txt" `
  --firmware "I:\LG-GS290-Rebirth\results\extracted\firmware" `
  --megalab-zip "GS290_MegaLab_v8_OneShot.zip" `
  --run-unicorn --cases 2048 --jobs 4 --seed 0x290C `
  --out "GS290_Combined_Results"
~~~

`--run-unicorn` использует **существующий** MegaLab v8 и только
офлайновые сегменты V10C. Сначала сверяются два ожидаемых SHA-256; при
несовпадении запуск запрещён. Данные для реального телефона не
формируются. Файлы исходных тестов и трасс хранятся в out/unicorn_runs.

### Единый результат

- `GS290_Combined_Results/MEGASUITE.txt` — сводка для человека;
- `MEGASUITE.json` — машинный отчёт, статусы, аномалии и контрольные суммы;
- `interesting_cases.zip` — исходные DEFLATE-входы и трассы
  первых 20 случаев физического выхода за границу массива;
- `evidence_for_review.zip` — небольшой архив для следующего анализа
  (TXT + JSON + интересные случаи);
- `unicorn_runs/` — полный ARM-набор, если запускали `--run-unicorn`.

`RETURNED_SUCCESS`, повреждение стека, неизменённый LR и наблюдаемые
свойства J2ME анализируются **раздельно**, без ложного вывода об RCE.

**Не загружайте в публичный репозиторий полный TXT, содержащий
персональные/локальные данные.** Перед отправкой можно отредактировать
сведения о сети, носителях и платформе.

## 3. Автоматическая проверка

GitHub Actions собирает CLDC 45.3 + StackMap JAR/JAD, проверяет
целостность контрольного DEFLATE, реальный номер версии и проводит
синтетические E2E-тесты PC MegaSuite без запуска реального ARM firmware.
Экспериментальные повреждённые JAR не публикуются как артефакты CI.
